# Daily Research Log Template

Create `data/YYYY-MM-DD/research_log.md` during every live daily run. This file is an internal audit trail; the reader-facing report can remain concise.

```markdown
# BIT Research Log — YYYY-MM-DD

## Runtime
| Field | Value |
|---|---|
| HKT start | |
| HKT cutoff / completion | |
| U.S. completed session used | |
| HK completed session used | |
| HK intraday status / cutoff | |
| Next U.S. session | |

## Prior thesis review
| Prior thesis / watch item | Status | Evidence | Source |
|---|---|---|---|

## Source register
| Market | Tier | Source | URL | Accessed HKT | What was read | Use / limitation |
|---|---|---|---|---|---|---|

## Facts
| Market | Claim | Value / event | Timestamp / session | Source | Confidence |
|---|---|---|---|---|---|

## Reported context
| Claim | Outlet attribution | Why it may explain price action | Limitation |
|---|---|---|---|

## William’s View / interpretation
| Interpretation | Evidence | Positive confirmation | Negative revision condition |
|---|---|---|---|

## Unresolved, unavailable, or conflicting claims
| Item | Why unresolved | Source / attempt | Impact on report |
|---|---|---|---|
```

Never state that a complete article was read unless its accessible body, tables, and relevant visual context were actually reviewed. Never delete an important unresolved item merely because it complicates the narrative.
